## 为什么适合自然语言

<CardGrid>
	<Card title="零翻译成本" icon="rocket">
		"年龄大于 18 的北京用户，按注册时间倒序" 就是 `age|gt=18`、`city=北京`、`od=-create_time`。
		`字段 → 操作符 → 值` 与中英文语序同构，比链式 builder API 出错率低得多。
	</Card>
	<Card title="参数是数据不是代码" icon="document">
		条件以 `Map` / JSON 传入，天然适配 Function Calling，也便于服务端校验与回放。
		复杂逻辑用 `lg` 表达式（`!(a,b)`），`LogicNode#toTreeString()` 打印出来即可自检。
	</Card>
	<Card title="接口小、约定强" icon="setting">
		入口只有 `create / updateByIds / deleteByIds / get / getByPages / getByIds / aggregation`，
		第一参数统一 `DSLContext`。驼峰自动转下划线、JSON 列自动序列化、`p/pc/pg` 分页，
		不需要映射配置与样板代码。
	</Card>
	<Card title="安全边界清晰" icon="padlock">
		值全走占位符绑定；字段名/排序键/分组字段逐段过标识符白名单，函数只认
		`FilamentsConfig.sqlFuncList` 且参数限数字字面量；非法输入抛错而不是拼进 SQL。
	</Card>
</CardGrid>

## 三十秒上手

```java
// 一个实例对应一张表：Filaments 是抽象类，模型类型取自 extends Filaments<User> 的泛型实参
var userFilament = new Filaments<User>("user") {
    @Override
    public ValidatorBuilder<User> initValidator() {
        return new ValidatorBuilder<>();
    }
};

// 年龄是 22 或 23 的用户
var users = userFilament.get(db, new HashMap<>() {{
    put("age|in", List.of(22, 23));
}});
```
